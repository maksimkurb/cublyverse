# WebApp

WebApp — единое приложение Cublyverse: оно открывается как Telegram Mini App,
как обычная страница в браузере (и, в перспективе, как виджет Matrix). Один и
тот же бандл отдаёт Go-бинарник по `/app/`, поэтому отдельного фронтенд-сервера в
проде нет.

Документ описывает устройство `web/`, мост к хосту, вход, маршрутизацию, экран
напоминаний, разработку и тесты. Правила добавления новой фичи — в конце.

## Что умеет

- вход из Telegram Mini App (Bearer-сессия в памяти) и из браузера (HttpOnly
  cookie);
- главный экран со списком фич и профилем (часовой пояс);
- «Напоминания»: список как будильники, переключатель «включено», модальный
  редактор с несколькими временами, днями недели или месяцами, интервалом
  повтора и удалением в два касания.

## Структура

    api/
      client.ts               openapi-fetch + middleware авторизации; типы API
      query.ts                openapi-react-query поверх того же клиента
      authMiddleware.ts       Bearer, Content-Type для cookie, повтор 401
      errors.ts               текст ошибки API для показа
      schema.d.ts             сгенерированные типы (руками не править)
    auth/

## Мост к хосту

Компоненты не обращаются к `Telegram.WebApp` и `window.confirm` напрямую: всё
идёт через `HostBridge` (`web/src/host/types.ts`). Это позволяет одному коду
работать в трёх окружениях и подменять хост в тестах.

```ts
interface HostBridge {
  kind: "telegram" | "matrix" | "browser";
  isTelegram: boolean;
  theme: "light" | "dark";
  initData: string;
  init(): void;                 // тема, ready(), expand()
  onThemeChange(listener): () => void;
  haptic(kind): void;
  showAlert(message): Promise<void>;
  showConfirm(message): Promise<boolean>;
  openLink(url): void;          // same-origin — в этом же webview
  close(): void;
  backButton: { show, hide, onClick };
}
```

### Определение хоста

1. `window.Telegram.WebApp.initData` непустой → `telegram`.
2. страница во фрейме, а во фрагменте URL (или query для старых виджетов) есть
   `widgetId` → `matrix`.
3. иначе → `browser`.

Адрес маршрута — путь (`/app/reminders`), поэтому фрагмент Telegram
(`#tgWebAppData=…`) остаётся нетронутым.

### Тема

- Telegram: `themeParams` копируются в `--tg-theme-*` на `<html>`, `colorScheme`
  становится `data-theme`. telegram-ui читает те же переменные, поэтому все
  компоненты автоматически следуют теме клиента; смена темы приходит событием
  `themeChanged`.
- Браузер: `prefers-color-scheme`, с подпиской на изменения.
- `AppRoot` получает `appearance` из моста, поэтому светлая и тёмная темы
  работают и без Telegram.

CSS telegram-ui импортируется из npm-пакета
(`@telegram-apps/telegram-ui/dist/styles.css`), а не с CDN: приложение работает
офлайн из встроенного бандла. Единственный внешний скрипт —
`https://telegram.org/js/telegram-web-app.js` в `index.html`, как требует
документация Telegram; вне Telegram он просто не создаёт `window.Telegram`.

### Haptics, диалоги, кнопка «назад», закрытие

- `haptic("selection" | "success" | "warning" | "error")` в Telegram вызывает
  `HapticFeedback.selectionChanged()` / `notificationOccurred()`, в браузере —
  no-op.
- `showAlert`/`showConfirm` — нативные диалоги Telegram или `window.alert`/
  `confirm`.
- Кнопка «назад»: стопка обработчиков (`useHostBackButton`). Экран регистрирует
  переход на главную, открытый редактор — закрытие; при закрытии редактора
  обработчик экрана снова становится активным.
- `openLink` для относительного или same-origin адреса использует
  `location.assign` — это важно для привязки аккаунта: следующая страница
  должна видеть `initData` того же Telegram-аккаунта. Внешние ссылки уходят в
  `Telegram.WebApp.openLink` или новую вкладку.

### Matrix

Ветка Matrix — задокументированная заглушка: виджет распознаётся (чтобы не
сломать встраивание), но ведёт себя как браузер. Вход через Matrix OpenID и
Widget API — в бэклоге (`docs/PLAN.md` §7).

## Вход

Одна и та же серверная сессия, два транспорта. Подробности сервера —
[docs/API.md](API.md).

### Telegram Mini App

```text
страница открыта в Telegram
        │
        ▼
host.initData ──POST /api/v1/auth/telegram {init_data}──► сервер
        │                                                  │
        │   подпись HMAC, auth_date ≤ 24 ч, user.id         │
        │                                                  │
        ├── status=ok ─────────────► токен в память ───────┤
        │                            GET /api/v1/me        │
        │                                                  │
        └── status=link_required ──► экран «Нужно привязать аккаунт»
                                     кнопка открывает link_url в этом webview
```

- Токен живёт только в модуле `auth/session.ts`; `localStorage` не
  используется. Каждое открытие Mini App присылает свежий `initData` и получает
  новую сессию.
- Каждый запрос получает `Authorization: Bearer <token>` в middleware
  `openapi-fetch`.
- Ответ `401` → один повторный `POST /auth/telegram` (общий для всех
  одновременных запросов), затем ровно один повтор исходного запроса с новым
  токеном. Второй `401` уже показывается пользователю.
- `link_required` не считается ошибкой сессии: экран привязки не перекрывается
  экраном «сессия истекла».

### Браузер

```text
GET /api/v1/me ──200──► приложение
        │
        └──401──► экран «Нужно войти»
                   ссылка /auth/login?return_to=/app/
                        │
                        ▼
                   OIDC → callback → HttpOnly cookie cv_session
                        │
                        ▼
                   303 на /app/
```

Токен в JavaScript не попадает. Middleware не ставит `Authorization` без
Bearer-токена, cookie уходит автоматически. Изменяющим запросам (включая
`DELETE` без тела) middleware добавляет `Content-Type: application/json` —
сервер требует это для cookie-сессий (защита от CSRF).

Выход (`POST /auth/logout`) показывается в браузере; в Telegram кнопки нет,
потому что сессия живёт до закрытия Mini App.

## Маршрутизация

Выбран **history-роутер под базой `/app/`** (`web/src/router/router.tsx`):

- `/app/` — главный экран, `/app/reminders` — напоминания, `/app/profile` —
  профиль;
- переходы — `history.pushState`, без перезагрузки;
- сервер уже отдаёт `index.html` на любой `/app/*` (SPA-fallback), поэтому
  перезагрузка и глубокая ссылка работают без отдельного правила на бэкенде;
- в отличие от hash-роутера, адрес не трогает фрагмент, в котором Telegram
  передаёт `#tgWebAppData=…`; перезагрузка Mini App сохраняет `initData`;
- адрес виден серверу (логи, будущая аналитика), а ссылка вида
  `/app/reminders` выглядит обычной.

Плата: любой хостинг должен отдавать `index.html` на неизвестные пути под
`/app/`; наш Go-бинарник это делает (`web/embed.go`), и smoke-тест проверяет
`/app/reminders/42`.

Глубокие ссылки: `/app/reminders`. `return_to` после OIDC принимает только
относительные пути этого сайта (`docs/API.md`), поэтому вход всегда возвращает
на `/app/`.

## Данные

- `web/src/api/client.ts` — типизированный `openapi-fetch` клиент, база
  `/api/v1`.
- `web/src/api/query.ts` — `openapi-react-query` поверх него; хуки сохраняют
  типы операций из `schema.d.ts`.
- Список напоминаний: `$api.useQuery("get", "/reminders")`, ключ
  `["get", "/reminders"]` (формат библиотеки).
- Мутации create/update/delete инвалидируют этот ключ.
- Типы (`Me`, `Reminder`, тела запросов) реэкспортируются из `client.ts`, чтобы
  экраны не зависели от структуры `paths`.
- `GET /me` и `PATCH /me` — профиль и часовой пояс; после `PATCH` обновлённый
  профиль кладётся в контекст авторизации.

Схема API — источник правды: при изменении `api/openapi.yaml` запускается
`make gen`, `schema.d.ts` перегенерируется, и несовпадение ловится `make check`.

## Экран «Напоминания»

### Список

- время крупно (27 px, полужирное), текст напоминания, подпись
  `<расписание> · повтор каждые N мин`, вторая строка — «Следующее: …» или
  «Ждёт подтверждения · следующий повтор …» (в часовом поясе напоминания,
  `ru-RU`);
- расписание: все 7 дней — «Каждый день», иначе «Пн, Ср, Пт»; один день месяца
  — «19-е число каждого месяца», несколько — «1, 15, 30 числа месяца»;
- переключатель включает и выключает напоминание: оптимистично, при ошибке
  откат и диалог; выключенная строка приглушена;
- нажатие на строку (кроме переключателя) открывает редактор;
- состояния: «Загрузка…», «Нет напоминаний» с подсказкой, блок ошибки с
  кнопкой «Повторить»;
- внизу большая кнопка «＋ Добавить напоминание».

### Редактор

`telegram-ui` `Modal` с заголовком «Новое напоминание» / «Изменить
напоминание» и кнопкой закрытия. Поля:

| Поле | Поведение |
|---|---|
| «Что напомнить» | textarea, до 1500 символов |
| «Время», «Ещё время» | `type=time`, «×» у каждого времени, «+ Добавить время» |
| «Расписание» | «По дням недели» / «По дням месяца» |
| Дни недели | чипы Пн..Вс, ISO-дни, мультивыбор |
| «Дни месяца» | числа через запятую/пробел/точку с запятой, 1..31, дубликаты убираются, сортировка |
| «Повторять, минут» | 1..1440 |
| «Включено» | переключатель |

- Каждое дополнительное время — **отдельное напоминание**: при создании это
  отдельные `POST`, при редактировании первое время уходит в `PUT`, остальные —
  новыми `POST`.
- Часовой пояс нового напоминания — из профиля (`GET /me`), с откатом на
  `Intl.DateTimeFormat().resolvedOptions().timeZone`; при редактировании
  сохраняется часовой пояс напоминания.
- Проверка на клиенте повторяет тексты сервера: пустой текст, отсутствие
  времени/дня, неверное время, дни вне диапазона, интервал повтора. Сообщение
  показывается в блоке ошибки внутри модального окна.
- «Удалить напоминание» требует второго нажатия «Подтвердить удаление»;
  состояние сбрасывается, потому что редактор при закрытии размонтируется.
- Haptics: выбор, успех и ошибка.

## Как добавить экран фичи

1. **API.** Если нужны новые операции — сначала `api/openapi.yaml` (summary,
   description, схемы, примеры), затем `make gen` и реализация на сервере
   (`docs/API.md`). Если операций хватает, бэкенд не трогаем.
2. **Каталог.** `web/src/features/<name>/index.ts`:

   ```ts
   import type { FeatureScreen } from "../types";
   import MyScreen from "./MyScreen";

   export const myFeature: FeatureScreen = {
     id: "my-feature",
     title: "Моя фича",
     icon: "✨",
     route: "/my-feature",
     component: MyScreen,
   };
   ```

3. **Экран.** Компонент в том же каталоге: `usePageTitle`, при необходимости
   `useHostBackButton(() => navigate("/"))`, данные через `$api`, разметка из
   `telegram-ui`, стили — на переменных `--tgui--*`.
4. **Реестр.** Одна строка в `web/src/features/registry.ts`:

   ```ts
   export const features: FeatureScreen[] = [remindersFeature, myFeature];
   ```

   Главный экран и роутер подхватят фичу автоматически.
5. **Чистые помощники.** Форматирование, разбор ввода, маппинг в тело запроса —
   отдельные модули без React и функций с побочными эффектами.
6. **Тесты.** Юнит-тесты помощников, компонентные тесты формы/списка на
   Vitest + Testing Library + jsdom (`pnpm test`).
7. **Документация.** Раздел в `docs/FEATURES.md` и, если появились новые
   экраны или правила, здесь.

## Разработка

```bash
cd web
pnpm install
pnpm dev          # http://localhost:5173/app/
```

Vite проксирует `/api` и `/auth` на `http://127.0.0.1:8080` (см.
`vite.config.ts`), поэтому бэкенд запускается отдельно:

```bash
make dev          # бэкенд на :8080 с конфигурацией из .env
```

Cookie-сессия работает через прокси: `Set-Cookie` от бэкенда относится к
`localhost:5173`, и браузер отправляет её дальше.

Если OIDC не настроен, браузерный вход недоступен; для проверки экранов без
входа можно открыть Mini App в Telegram либо временно работать с API-моками в
тестах.

Сборка и проверки:

```bash
make gen          # Go, sqlc, web/src/api/schema.d.ts
make check        # gen без диффа + go vet + ESLint + tsc + тесты
make build        # web/dist, затем bin/cublyverse
```

`make build` встраивает `web/dist` в бинарник (`web/embed.go`): `/app/` отдаёт
`index.html`, `/app/assets/*` — файлы с долгим кешем, неизвестный путь под
`/app/` — снова `index.html` (SPA-fallback). Если сборки нет, отдаётся понятная
страница «WebApp не собран», а не паника.

## Тесты

```bash
cd web && pnpm test
```

- `vitest` + `@testing-library/react` + `jsdom`, очистка после каждого теста
  (`src/test/setup.ts`).
- Общие помощники: `src/test/render.tsx` (AppRoot + фейковый хост),
  `src/test/fakeHost.ts`, `src/test/fixtures.ts`.
- Покрыто:
  - форматирование расписания и дат, разбор дней месяца, валидация и маппинг
    формы, разветвление на несколько запросов;
  - форма: сообщения валидации, маппинг, удаление в два касания, часовой пояс
    при редактировании;
  - экран: строки-будильники, пустое состояние, ошибка загрузки, оптимистичное
    переключение с откатом;
  - авторизация: `POST /auth/telegram` (успех, `link_required`, ошибка),
    повтор `401` ровно один раз, браузерный `401` → экран «Нужно войти»,
    привязка аккаунта;
  - определение хоста и мост Telegram (тема, haptics).

## Ограничения

- Matrix-виджет: только определение и фолбэк на браузер; OpenID-вход — бэклог.
- Токен Mini App не переживает перезагрузку страницы: при перезагрузке
  приложение заново обменивает `initData` на сессию.
- Часовой пояс выбирается из `Intl.supportedValuesOf("timeZone")`; в старых
  движках используется короткий встроенный список.
