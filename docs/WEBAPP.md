# WebApp

WebApp — единое приложение Cublyverse: оно открывается как Telegram Mini App,
как обычная страница в браузере (и, в перспективе, как виджет Matrix). Один и
тот же бандл отдаёт Go-бинарник по `/app/`, поэтому отдельного фронтенд-сервера в
проде нет.

Документ описывает устройство `web/`, мост к хосту, вход, маршрутизацию, экран
напоминаний, разработку и тесты. Правила добавления новой фичи — в конце.

## Что умеет

- вход из Telegram Mini App (Bearer-сессия в памяти) и из браузера (HttpOnly
  cookie);
- навигация по разделам: нижняя панель на телефоне, боковое меню на широком
  экране; `/app/` открывает первую фичу (напоминания);
- «Напоминания»: карточка «Ждёт отметки» с кнопкой «Выполнено», фильтр «Все /
  Повторяющиеся / Один раз», список карточек с переключателем «включено»,
  редактор с пресетами повтора (день, неделя, месяц, n-й день недели, год,
  рабочие дни, своё расписание), датой начала и условием окончания, интервалом
  повтора и удалением в два касания;
- «Профиль» → «Токены и MCP»: адрес MCP-сервера, список персональных токенов, создание с выбором областей
  и срока, одноразовый показ секрета и отзыв в два касания;
- «Склад» — один экран с вкладками «Запасы», «Закупки», «Проекты» и
  «Каталог». «Запасы»: переключатель пространства, кнопка «Добавить в
  запасы», остатки материалов с фильтрами по
  категории и производителю, поиском и порогом «мало осталось», быстрые ±1,
  точная правка количества, места хранения и заметок;
- «Закупки» (вкладка «Склада»): список покупок пространства, сгруппированный по статусам
  «Хочу купить» / «Заказано» / «Куплено», с приоритетом, количеством, заметкой и
  ссылками на магазины; добавление из каталога или свободным текстом, правка,
  отметка «Куплено» с выбором «добавить в запасы»;
- «Каталог» (вкладка «Склада»): поиск по общему каталогу и частным позициям, фильтр «только в
  запасах», добавление на склад, создание частной позиции по форме категории и
  связывание её с каталожной;
- «Проекты» (вкладка «Склада»): список проектов, страница проекта с планом материалов (план,
  использовано, остаток, дефицит), списание материала, добавление материалов из
  каталога и перенос недостающего в закупки;
- пространства: у каждого мини-аппа своя кнопка с переключением,
  участниками и настройками, а без пространства — онбординг;
- «Профиль»: часовой пояс, привязанные мессенджеры, выход.

## Мост к хосту

Компоненты не обращаются к `Telegram.WebApp` и `window.confirm` напрямую: всё
идёт через `HostBridge` (`web/src/host/types.ts`). Это позволяет одному коду
работать в трёх окружениях и подменять хост в тестах.

```ts
interface HostBridge {
  kind: "telegram" | "matrix" | "browser";
  isTelegram: boolean;
  theme: "light" | "dark";
  initData: string;
  init(): void;                 // тема, ready(), expand()
  onThemeChange(listener): () => void;
  haptic(kind): void;
  showAlert(message): Promise<void>;
  showConfirm(message): Promise<boolean>;
  openLink(url): void;          // same-origin — в этом же webview
  close(): void;
  backButton: { show, hide, onClick };
}
```

### Определение хоста

1. `window.Telegram.WebApp.initData` непустой → `telegram`.
2. страница во фрейме, а во фрагменте URL (или query для старых виджетов) есть
   `widgetId` → `matrix`.
3. иначе → `browser`.

Адрес маршрута — путь (`/app/reminders`), поэтому фрагмент Telegram
(`#tgWebAppData=…`) остаётся нетронутым.

### Тема

- Telegram: `colorScheme` становится `data-theme` на `<html>`, `themeParams`
  копируются в `--tg-theme-*`; смена темы приходит событием `themeChanged`.
- Браузер: `prefers-color-scheme`, с подпиской на изменения.
- `styles.css` переключает палитру по `data-theme`: у приложения своя
  айдентика, цвета клиента Telegram оно не перенимает, только светлую или
  тёмную схему.

Внешний ресурс один: скрипт `https://telegram.org/js/telegram-web-app.js` в
`index.html`, как требует документация Telegram (вне Telegram он просто не
создаёт `window.Telegram`). Шрифты бренда встроены в бандл: переменные
woff2 (латиница и кириллица) лежат в `web/public/fonts/`, подключены через
`@font-face` в `styles.css`, отдаются по `/app/fonts/…` (кэш 7 дней) и работают
офлайн. Серверные страницы входа берут те же файлы. Лицензия шрифтов — OFL-1.1,
тексты рядом (`LICENSE-*.txt`). Чтобы обновить шрифт, замените файлы,
сохранив имена.

### Haptics, диалоги, кнопка «назад», закрытие

- `haptic("selection" | "success" | "warning" | "error")` в Telegram вызывает
  `HapticFeedback.selectionChanged()` / `notificationOccurred()`, в браузере —
  no-op.
- `showAlert`/`showConfirm` — нативные диалоги Telegram или `window.alert`/
  `confirm`.
- Кнопка «назад»: стопка обработчиков (`useHostBackButton`). Разделы верхнего
  уровня её не показывают (между ними переключает навигация); открытый
  редактор или диалог регистрирует закрытие.
- `openLink` для относительного или same-origin адреса использует
  `location.assign` — это важно для привязки аккаунта: следующая страница
  должна видеть `initData` того же Telegram-аккаунта. Внешние ссылки уходят в
  `Telegram.WebApp.openLink` или новую вкладку.

### Matrix

Ветка Matrix — задокументированная заглушка: виджет распознаётся (чтобы не
сломать встраивание), но ведёт себя как браузер. Вход через Matrix OpenID и
Widget API — в бэклоге (`docs/PLAN.md` §7).

## Вход

Одна и та же серверная сессия, два транспорта. Подробности сервера —
[docs/API.md](API.md).

### Telegram Mini App

```text
страница открыта в Telegram
        │
        ▼
host.initData ──POST /api/v1/auth/telegram {init_data}──► сервер
        │                                                  │
        │   подпись HMAC, auth_date ≤ 24 ч, user.id         │
        │                                                  │
        ├── status=ok ─────────────► токен в память ───────┤
        │                            GET /api/v1/me        │
        │                                                  │
        └── status=link_required ──► экран «Нужно привязать аккаунт»
                                     кнопка открывает link_url в этом webview
```

- Токен живёт только в модуле `auth/session.ts`; `localStorage` не
  используется. Каждое открытие Mini App присылает свежий `initData` и получает
  новую сессию.
- Каждый запрос получает `Authorization: Bearer <token>` в middleware
  `openapi-fetch`.
- Ответ `401` → один повторный `POST /auth/telegram` (общий для всех
  одновременных запросов), затем ровно один повтор исходного запроса с новым
  токеном. Второй `401` уже показывается пользователю.
- `link_required` не считается ошибкой сессии: экран привязки не перекрывается
  экраном «сессия истекла».

### Браузер

```text
GET /api/v1/me ──200──► приложение
        │
        └──401──► экран «Нужно войти»
                   ссылка /auth/login?return_to=/app/
                        │
                        ▼
                   OIDC → callback → HttpOnly cookie cv_session
                        │
                        ▼
                   303 на /app/
```

Токен в JavaScript не попадает. Middleware не ставит `Authorization` без
Bearer-токена, cookie уходит автоматически. Изменяющим запросам (включая
`DELETE` без тела) middleware добавляет `Content-Type: application/json` —
сервер требует это для cookie-сессий (защита от CSRF).

Выход (`POST /auth/logout`) показывается в браузере; в Telegram кнопки нет,
потому что сессия живёт до закрытия Mini App.

## Маршрутизация

Выбран **history-роутер под базой `/app/`** (`web/src/router/router.tsx`):

- `/app/` — первая фича из реестра (напоминания), `/app/reminders` —
  напоминания, `/app/craft` — склад,
  `/app/profile` — профиль;
- переходы — `history.pushState`, без перезагрузки;
- сервер уже отдаёт `index.html` на любой `/app/*` (SPA-fallback), поэтому
  перезагрузка и глубокая ссылка работают без отдельного правила на бэкенде;
- в отличие от hash-роутера, адрес не трогает фрагмент, в котором Telegram
  передаёт `#tgWebAppData=…`; перезагрузка Mini App сохраняет `initData`;
- адрес виден серверу (логи, будущая аналитика), а ссылка вида
  `/app/reminders` выглядит обычной.

Плата: любой хостинг должен отдавать `index.html` на неизвестные пути под
`/app/`; наш Go-бинарник это делает (`web/embed.go`), и smoke-тест проверяет
`/app/reminders/42`.

Глубокие ссылки: `/app/reminders`. `return_to` после OIDC принимает только
относительные пути этого сайта (`docs/API.md`), поэтому вход всегда возвращает
на `/app/`.

## Данные

- `web/src/api/client.ts` — типизированный `openapi-fetch` клиент, база
  `/api/v1`.
- `web/src/api/query.ts` — `openapi-react-query` поверх него; хуки сохраняют
  типы операций из `schema.d.ts`.
- Список напоминаний: `$api.useQuery("get", "/reminders")`, ключ
  `["get", "/reminders"]` (формат библиотеки).
- Мутации create/update/delete/complete инвалидируют этот ключ.
- Типы (`Me`, `Reminder`, тела запросов) реэкспортируются из `client.ts`, чтобы
  экраны не зависели от структуры `paths`.
- `GET /me` и `PATCH /me` — профиль и часовой пояс; после `PATCH` обновлённый
  профиль кладётся в контекст авторизации.

Схема API — источник правды: при изменении `api/openapi.yaml` запускается
`make gen`, `schema.d.ts` перегенерируется, и несовпадение ловится `make check`.

## Экран «Напоминания»

### Список

- сверху — янтарная карточка «Ждёт отметки» для каждого напоминания с
  неподтверждённым срабатыванием; кнопка «Выполнено» вызывает
  `POST /reminders/{id}/complete`, как кнопка в чате;
- фильтр «Все / Повторяющиеся / Один раз» (на клиенте, по `schedule_kind`);
- карточка: текст напоминания, дни чипами (семь квадратов недели, числа месяца
  или короткая подпись «2-й Вт» / «Один раз» / «Каждый день»), время
  моноширинным шрифтом, строка статуса — «Следующее: …», «Ждёт подтверждения ·
  следующий повтор …», «Завершено» или «Выключено» (в часовом поясе
  напоминания, `ru-RU`);
- чипы дней декоративные (`aria-hidden`); для скринридера рядом скрытая строка
  `<расписание> · повтор каждые N мин`: расписание описывает `describeSchedule`
  теми же словами, что бот (`каждую неделю по пн, ср, пт в 09:30`, `каждое 15-е
  число месяца`, `каждый второй вторник месяца`, `20.03.2027 в 10:00 (один
  раз)`);
- переключатель включает и выключает напоминание: оптимистично, при ошибке
  откат и диалог; выключенная карточка приглушена;
- нажатие на карточку (кроме переключателя) открывает редактор;
- состояния: «Загрузка…», «Нет напоминаний» с подсказкой, блок ошибки с
  кнопкой «Повторить»;
- в шапке кнопка «Новое» (доступное имя — «Новое напоминание»).

### Редактор

`Sheet` (Base UI `Dialog`) с заголовком «Новое напоминание» / «Изменить
напоминание» и кнопкой закрытия: на телефоне выезжает снизу, на широком экране
стоит по центру. Поля:

| Поле | Поведение |
|---|---|
| «Что напомнить» | textarea, до 1500 символов |
| «Время», «Ещё время» | `type=time`, «×» у каждого времени, «+ Добавить время» |
| «Дата» / «Начать с» | `type=date`; дата разового напоминания или первый возможный день повтора |
| «Повтор» | `SelectField` с пресетами: «Не повторять», «Каждый день», «Каждую неделю в <день даты>», «Каждый месяц <число>-го числа», «Каждый месяц <n-й день недели>», «Каждый год», «Рабочие дни пн–пт», «Своё…» |
| «Своё…» | интервал и единица (день/неделя/месяц/год), при неделе — чипы Пн..Вс, при месяце — сегменты «Числа месяца» / «День недели»; для чисел — строка через запятую/пробел/точку с запятой (1..31), для дня недели — «Какой по счёту» (1..4 или последний) и день недели |
| «Окончание» | «Никогда», «До даты» (`type=date`) или «После N раз» (1..10000) |
| «Повторять, минут» | 1..1440 |
| «Включено» | переключатель |

- Каждое дополнительное время — **отдельное напоминание**: при создании это
  отдельные `POST`, при редактировании первое время уходит в `PUT`, остальные —
  новыми `POST`.
- Часовой пояс нового напоминания — из профиля (`GET /me`), с откатом на
  `Intl.DateTimeFormat().resolvedOptions().timeZone`; при редактировании
  сохраняется часовой пояс напоминания.
- Проверка на клиенте повторяет тексты сервера: пустой текст, отсутствие
  времени/дня, неверное время, дни вне диапазона, интервал повтора. Сообщение
  показывается в блоке ошибки внутри модального окна.
- «Удалить напоминание» требует второго нажатия «Подтвердить удаление»;
  состояние сбрасывается, потому что редактор при закрытии размонтируется.
- Haptics: выбор, успех и ошибка.

## Профиль: «Токены и MCP»

Раздел внутри профиля (`web/src/features/tokens/TokensSection.tsx`); старая
ссылка `/app/tokens` открывает профиль.

`web/src/features/tokens` — управление персональными токенами, которыми
подключаются MCP-клиенты и скрипты (`docs/MCP.md`).

### Список

- сверху тёмная карточка «MCP-сервер» с адресом `<origin>/mcp` и кнопкой
  копирования;
- имя, `cv_pat_<префикс>…`, области доступа чипами (`reminders:read`), дата создания,
  последнее использование и срок («Бессрочно» или «до дд.мм.гггг»);
- состояние: «Активен», «Отозван», «Истёк» (отзыв важнее истечения); неактивные
  строки приглушены и не имеют кнопки отзыва;
- отзыв — в два касания: «Отозвать» → «Подтвердить отзыв»; ошибка показывается
  нативным диалогом хоста;
- пустое состояние и блок ошибки с кнопкой «Повторить», как у напоминаний.

### Создание и одноразовый показ

- Кнопка «Новый» в шапке (доступное имя — «Новый токен») открывает диалог: название (1..80),
  чекбоксы областей (`profile:read`, `reminders:read`, `reminders:write`) и
  срок (бессрочно / 30 / 90 / 365 дней);
- клиентская проверка повторяет серверные тексты; сервер всё равно проверяет
  всё заново;
- после успешного `POST /tokens` открывается экран показа: предупреждение
  «Больше он не будет показан», само значение токена и кнопка «Скопировать»
  (при недоступном буфере обмена значение остаётся выделяемым вручную);
- секрет не сохраняется в состоянии дольше, чем открыт экран показа, и никогда
  не попадает в список: сервер хранит только sha256.

### Подключённые приложения

Под списком токенов (`ConnectionsSection`) показываются приложения, которым пользователь разрешил доступ через OAuth: название, области доступа, даты подключения и последнего использования. «Отключить» подтверждается вторым нажатием и отзывает все токены этого подключения (`DELETE /connections/{id}`). Пока подключений нет, раздел скрыт.

## Пространства мини-аппов

У напоминаний и склада свои пространства: расшарить склад можно, не открывая
напоминания. `features/workspaces/SpaceBar.tsx` стоит под заголовком
мини-аппа, в одной строке с ним и с действиями экрана (интерфейс сначала
мобильный: на ширине 340–390 px всё помещается без прокрутки вбок):

- без единого пространства это онбординг: название (по умолчанию «Личное») и
  кнопка «Начать»;
- иначе — кнопка с названием текущего пространства. Она открывает лист:
  переключение, «Новое пространство», участники с аватарами Gravatar, поиск
  кандидатов (кто уже входил), переименование и удаление.

Удаление участника, выход и удаление пространства — в два касания; последнего
участника сервер не отпускает (`409`). Выбор хранится в `localStorage`
(`cv.space.<app>`) в `try/catch`; исчезнувшее пространство заменяется первым из
списка.

Если в пространстве напоминаний больше одного участника, редактор показывает
«Кому присылать»; по умолчанию отмечен только автор. Подтвердить срабатывание
может любой участник.

## Экран «Склад»: «Запасы» и «Каталог»

`web/src/features/craft` — один экран с сегментами «Запасы» / «Каталог»,
общий переключатель пространства и общие фильтры.

«Добавить в запасы» (и «На склад» в каталоге) открывает `AddStockDialog`:
поиск позиции или создание своей, затем количество, которое прибавляется к
остатку, и необязательное место хранения.

### Запасы

- строка остатка: цветовой образец из `color_hex`, название, производитель и
  артикул, категория, место хранения, заметки, количество с единицей;
- быстрые кнопки «−1» / «+1» вызывают `POST .../adjust`; списание больше
  остатка показывает ошибку сервера;
- «Изменить» открывает лист с точным количеством, местом и заметками: `PUT`
  ставит количество, затем `PATCH` сохраняет место и заметки; там же «Убрать со
  склада» в два касания;
- фильтры: поиск (название, цвет, артикул), категория, производитель и
  переключатель «Мало осталось (≤ 5)» — он отправляет `max_qty=5`;
- пустые состояния различают «склад пуст» и «ничего не найдено».

### Каталог

- поиск по общему каталогу и частным позициям, фильтр «только в запасах»,
  категория и производитель;
- у результата виден остаток пространства; «На склад» — это `adjust` с
  `delta: 1`, поэтому первое добавление создаёт строку запаса;
- «Новая позиция» открывает форму своей позиции: категория склада, название,
  производитель (список с возможностью вписать нового), артикул, цвет
  `#RRGGBB` с образцом, название цвета, размер, единица склада (по умолчанию —
  `default_unit` категории) и поля категории. Название или артикул
  обязательны. Свою позицию можно «Изменить» той же формой и «Удалить» с
  подтверждением;
- у частной позиции есть «Связать»: поиск целевой каталожной позиции,
  `POST .../link` переносит остаток и удаляет частную запись; сервер требует
  совпадения единиц.

## Поиск по цвету и пипетка

`SearchBar.tsx` — строка поиска с кнопкой цвета; `useCraftSearch` превращает
введённый `#RRGGBB` в параметр `color` (без `#` это может быть артикул).
`ColorPickSheet.tsx` даёт пипетку по фото, системную палитру и поле HEX. Фото
рисуется в `canvas` (длинная сторона не больше 1600 пикселей) и не
отправляется на сервер; цвет — медиана маленького участка под пальцем
(`medianColor`), над пальцем показана лупа. Цвета из фото производителей
считает сервер. Строки результата показывают HEX, по которому они
сравнивались (`ColorTag`).

## Цвет и фото позиции

`features/craft/Swatch.tsx` показывает фото позиции (`image_proxy_url`), если оно
есть: один HEX не передаёт прозрачный и перламутровый бисер. Фото грузится
лениво через прокси сервера ([`API.md`](API.md)); в списках запасов, каталога,
закупок и проектов нажатие открывает его целиком. Без фото рисуется HEX, а
неизвестный цвет — штриховкой. Своей позиции ссылку на фото задаёт поле
«Ссылка на фото».

## Настройки склада

`features/craft/WarehouseSettings.tsx` — значок в строке заголовка. Разделы: «Категории» (название, единица по умолчанию, свои поля
типов «Текст», «Число», «Да / нет», «Список»), «Бренды» (официальные только
читаются), «Единицы», «Каталоги» (подключение DMC и PRECIOSA). Отказ в удалении
занятой записи показывается диалогом с текстом сервера. При создании склада
выбирается шаблон «Рукоделие» или «Пустой».

## Вкладка «Закупки»

`web/src/features/craft/PurchasesPanel.tsx` — список покупок выбранного
пространства, вторая вкладка экрана «Склад». В API и MCP он называется
`wishlist`.

- Записи сгруппированы по статусам: «Хочу купить», «Заказано», «Куплено»; в
  каждой группе сначала идут более важные приоритеты. Пустые группы скрыты.
- Карточка: название, чип приоритета («Важно» / «Очень важно»), количество с
  единицей, производитель, артикул и категория позиции каталога, остаток
  пространства и заметка.
- Ссылки на магазины — чипы: название магазина (или хост ссылки), цена с
  валютой и отметка «в наличии» / «нет в наличии». Каждая ссылка открывается в
  новой вкладке с `rel="noopener noreferrer"`.
- «Добавить в закупки» открывает лист: источник «Из каталога» или «Свободный текст».
  В режиме каталога — поиск и выбор позиции (её название подставляется
  сервером), затем количество, приоритет и заметка. Свободный текст требует
  название.
- «Изменить» — количество, приоритет, статус и заметка, а также управление
  ссылками: добавить ссылку (URL, магазин, цена, валюта, наличие) и убрать
  каждую существующую. Удаление записи — в два касания.
- «Куплено» открывает подтверждение с чекбоксом «Добавить в запасы»: для
  позиции каталога с количеством он отмечен по умолчанию, для свободного текста
  недоступен. После успеха карточка переезжает в группу «Куплено», а остаток
  растёт, если добавление выбрано.

## Вкладка «Проекты»

`web/src/features/craft/ProjectsPanel.tsx` — проекты выбранного пространства.

- Список карточек: название, число материалов и заметки. Нажатие открывает
  страницу проекта; кнопка «← Проекты» и системная кнопка «назад» возвращают к
  списку.
- Страница проекта: название и заметки, кнопки «Добавить материал»,
  «Недостающее в закупки» и «Изменить» (название, заметки, удаление в два
  касания).
- Материал: название и метаданные, «План», «Использовано», «На складе» и
  янтарный дефицит «Нужно купить: …», когда плана не хватает с учётом остатка.
- «Добавить материал» — поиск по каталогу и плановое количество (по умолчанию
  1); уже запланированные позиции в списке не повторяются. «План» у материала
  меняет количество, пустое поле очищает план; «Убрать» подтверждается
  диалогом хоста и не трогает остаток.
- «Использовать» спрашивает количество, списывает его со склада и увеличивает
  использованное; при нехватке показывается ошибка `409` сервера.
- «Недостающее в закупки» переносит положительные дефициты и сообщает, сколько
  записей добавлено (или что все уже там).

## Дизайн-система

Своя айдентика поверх примитивов [Base UI](https://base-ui.com): библиотека
даёт поведение (диалог, переключатель, чекбокс), весь вид — в `styles.css`.

| Что | Как |
|---|---|
| Знак | изометрический куб: лаймовая, чернильная и фиолетовая грани (`Logo`) |
| Цвета | `--ink` `#15171C`, фон `--bg` `#F3F4EF`, `--lime` `#C9F23D` — главное действие, `--violet` `#5546E8` — данные и фокус, `--amber` `#FFB25C` — «ждёт отметки», `--danger` — удаление |
| Форма | обводка 1.5 px (`--border`), радиус 10–12 px, жёсткая тень `--lift` (3 px без размытия) у главной кнопки и важных карточек |
| Шрифты | Unbounded — заголовки, Onest — текст, JetBrains Mono — время, токены, метки |
| Темы | светлая и тёмная, переключение по `data-theme` на `<html>` |

Правила:

- одна лаймовая кнопка (`variant="primary"`) на экран или диалог;
- цели касания не меньше 44 px; фокус — фиолетовая обводка 3 px;
- раскладка мобильная по умолчанию; с 860 px навигация становится боковым
  меню, с 640 px диалог встаёт по центру;
- иконки — inline SVG из `ui/icons.tsx`, без эмодзи и иконочных пакетов.

Страницы входа и привязки, которые отдаёт сервер (`internal/auth/pages.go`),
оформлены в том же стиле (тёмный экран с логотипом), но своим встроенным CSS.

## Как добавить экран фичи

1. **API.** Если нужны новые операции — сначала `api/openapi.yaml` (summary,
   description, схемы, примеры), затем `make gen` и реализация на сервере
   (`docs/API.md`). Если операций хватает, бэкенд не трогаем.
2. **Каталог.** `web/src/features/<name>/index.ts`:

   ```ts
   import type { FeatureScreen } from "../types";
   import MyScreen from "./MyScreen";

   export const myFeature: FeatureScreen = {
     id: "my-feature",
     title: "Моя фича", // короткое: это подпись в навигации
     icon: IconBell, // компонент из web/src/ui/icons.tsx
     route: "/my-feature",
     component: MyScreen,
   };
   ```

3. **Экран.** Компонент в том же каталоге: корень `<div className="page">` с
   шапкой `page__head`, `usePageTitle`, данные через `$api`, разметка из
   `web/src/ui/controls.tsx`, свои стили — на токенах из `styles.css`
   (`--surface`, `--line`, `--lime` и т. д.), чтобы работали обе темы.
4. **Реестр.** Одна строка в `web/src/features/registry.ts`:

   ```ts
   export const features: FeatureScreen[] = [remindersFeature, myFeature];
   ```

   Навигация и роутер подхватят фичу автоматически.
5. **Чистые помощники.** Форматирование, разбор ввода, маппинг в тело запроса —
   отдельные модули без React и функций с побочными эффектами.
6. **Тесты.** Юнит-тесты помощников, компонентные тесты формы/списка на
   Vitest + Testing Library + jsdom (`pnpm test`).
7. **Документация.** Раздел в `docs/FEATURES.md` и, если появились новые
   экраны или правила, здесь.

## Разработка

```bash
cd web
pnpm install
pnpm dev          # http://localhost:5173/app/
```

Vite проксирует `/api` и `/auth` на `http://127.0.0.1:8080` (см.
`vite.config.ts`), поэтому бэкенд запускается отдельно:

```bash
make dev          # бэкенд на :8080 с конфигурацией из .env
```

Cookie-сессия работает через прокси: `Set-Cookie` от бэкенда относится к
`localhost:5173`, и браузер отправляет её дальше.

Если OIDC не настроен, браузерный вход недоступен; для проверки экранов без
входа можно открыть Mini App в Telegram либо временно работать с API-моками в
тестах.

Сборка и проверки:

```bash
make gen          # Go, sqlc, web/src/api/schema.d.ts
make check        # gen без диффа + go vet + ESLint + tsc + тесты
make build        # web/dist, затем bin/cublyverse
```

`make build` встраивает `web/dist` в бинарник (`web/embed.go`): `/app/` отдаёт
`index.html`, `/app/assets/*` — файлы с долгим кешем, неизвестный путь под
`/app/` — снова `index.html` (SPA-fallback). Если сборки нет, отдаётся понятная
страница «WebApp не собран», а не паника.

## Тесты

```bash
cd web && pnpm test
```

- `vitest` + `@testing-library/react` + `jsdom`, очистка после каждого теста
  (`src/test/setup.ts`).
- Общие помощники: `src/test/render.tsx` (AppRoot + фейковый хост),
  `src/test/fakeHost.ts`, `src/test/fixtures.ts`.
- Покрыто:
  - форматирование расписания и дат, разбор дней месяца, валидация и маппинг
    формы, разветвление на несколько запросов;
  - форма: сообщения валидации, маппинг, удаление в два касания, часовой пояс
    при редактировании;
  - экран: строки-будильники, пустое состояние, ошибка загрузки, оптимистичное
    переключение с откатом;
  - токены: состояния «активен/отозван/истёк», подписи областей и сроков,
    валидация формы создания, двухшаговый отзыв, создание и одноразовый показ
    секрета с копированием;
  - запасы и каталог: строки остатка, быстрые ±1, фильтр малого количества,
    точная правка и удаление со склада, добавление на склад, создание частной
    позиции и связывание с каталогом;
  - закупки и проекты: группировка по статусам, чипы ссылок с
    `rel="noopener noreferrer"`, правка количества и статуса, отметка «Куплено» с
    выбором запасов, добавление из каталога, план/использование/дефицит
    материала, «Использовать» и перенос недостающего в закупки;
  - пространства: состав с аватарами, добавление кандидата, удаление в два
    касания, создание/переименование/удаление пространства и сохранение
    выбранного id в `localStorage` с устойчивостью к недоступному хранилищу;
  - авторизация: `POST /auth/telegram` (успех, `link_required`, ошибка),
    повтор `401` ровно один раз, браузерный `401` → экран «Нужно войти»,
    привязка аккаунта;
  - определение хоста и мост Telegram (тема, haptics).

## Ограничения

- Matrix-виджет: только определение и фолбэк на браузер; OpenID-вход — бэклог.
- Токен Mini App не переживает перезагрузку страницы: при перезагрузке
  приложение заново обменивает `initData` на сессию.
- Часовой пояс выбирается из `Intl.supportedValuesOf("timeZone")`; в старых
  движках используется короткий встроенный список.
